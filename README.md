# Менеджер речевых модулей

Браузерный помощник оператора колл-центра: ведёт по сценарию диалога с клиентом, подставляет данные клиента в текст, помогает отрабатывать возражения, позволяет визуально редактировать сценарий и вести базу **перезвонов** с авто-планированием следующего звонка.

Хронология изменений по версиям — в **`CHANGELOG.md`**.

---

## 🐣 Гайд для новичков (с нуля)

Ниже — пошаговая инструкция для тех, у кого пока нет ничего: ни Python, ни опыта. Делайте по шагам, всё просто.

### Шаг 1. Скачайте нужные файлы
Вам нужны **3 файла** (положите их в одну папку):
- `index.html` — само приложение;
- `start.py` — программа запуска;
- один файл для вашей системы:
  - **Windows** → `start_win.bat`;
  - **macOS** → `start_mac.command`.

> Скачать можно на странице репозитория: кнопка **Code → Download ZIP**, или скачать каждый файл по отдельности.

### Шаг 2. Положите файлы в одну папку
Например, создайте на рабочем столе папку `Менеджер` и положите туда все 3 файла. Важно: `index.html`, `start.py` и файл запуска должны быть **в одной папке**.

### Шаг 3. Запустите
- **Windows:** двойной клик по `start_win.bat`.
- **macOS:** двойной клик по `start_mac.command`. Если macOS спросит «файл загружен из интернета» — нажмите правой кнопкой по файлу → «Открыть» → «Открыть» один раз.

Откроется небольшое чёрное окно (консоль) и затем браузер с приложением.

### Шаг 4. А что с Python?
Для работы нужен **Python**. Но отдельно ничего устанавливать не нужно — файл запуска **сам всё сделает**:
- если Python уже есть — он просто запустится;
- если Python нет, но есть `py`-лаунчер — файл запуска **сам выполнит `py install default`**, подождёт установки и запустится (добавлять в PATH вручную не нужно — скрипт сам найдёт Python);
- если нет ни `python`, ни `py` — откроется страница загрузки Python (https://www.python.org/downloads/). Установите **Python Install Manager**, снова запустите файл — дальше всё автоматически.

> На **Windows** после установки `py`-лаунчера перезапустите `start_win.bat` — он сам доставит интерпретатор.
> На **macOS** Python 3 обычно уже есть; если нет — тот же механизм.

### Шаг 5. Пользуйтесь
Приложение откроется в браузере. Когда закроете консоль — сервер остановится. Чтобы снова открыть — просто запустите файл запуска ещё раз.

> **Короткая версия:** скачал 3 файла → положил в одну папку → запустил `start_win.bat` (или `start_mac.command`) → пользуешься. Если нужно — файл запуска сам доставит Python.

## 🚀 Запуск

### Быстрый запуск (Windows / macOS)
1. Положите файлы в любую папку (важно: `index.html` и `start.py` должны лежать рядом).
2. **Windows:** двойной клик по `start_win.bat`.
3. **macOS:** двойной клик по `start_mac.command`. Если система блокирует неизвестный файл — ПКМ → «Открыть» → «Открыть» один раз.
4. **Любая ОС (универсально):** `python start.py` (нужен установленный Python 3).

**Как устроено:** вся логика запуска — в одном файле `start.py`. Файлы `start_win.bat` / `start_mac.command` — лишь тонкие «двойные клики», которые запускают `start.py` на своей ОС. Поэтому править нужно только `start.py`.

`start.py` при запуске:
- **автоматически обновляет все файлы** из репозитория (`index.html`, сам `start.py`, `start_win.bat`, `start_mac.command`, userscript, README, CHANGELOG) — без запроса, просто сообщает «обновлено». Старая версия `index.html` сохраняется как `index.html.bak`;
- если обновился сам `start.py` — перезапускается, чтобы изменения применились;
- запускает локальный сервер и открывает приложение в браузере.

### Ручной запуск
```
python -m http.server 8000
# затем в браузере: http://localhost:8000/index.html
```

> **Важно про браузер.** Полноценная работа с файлами (автосохранение, бэкапы) доступна в **Chrome / Edge** (File System Access API). В Safari/Firefox файлы открываются на чтение, а сохранение идёт через скачивание.

## 💾 Как сохранять данные в файлы

Приложение работает в браузере: пока страница открыта — данные в памяти. Чтобы правки **записывались в файлы** и не терялись:

1. Откройте приложение через локальный сервер (см. «Запуск») в **Chrome/Edge**.
2. Перейдите в **⚙ Редактор → Настройки → 💾 Файлы и бэкапы**.
3. Для каждого файла (сценарий, возражения, перезвоны) нажмите **«📂 Открыть файл…»** и выберите соответствующий `.json` (или создайте через «💾 Сохранить как…»).
4. Включите переключатель **«автосохранение в привязанные файлы»** (по умолчанию включён). После этого все изменения автоматически записываются в привязанные файлы.

- **Ручное сохранение/бэкап:** кнопка «💾 Сохранить + бэкап» вверху Редактора — сохраняет файлы и создаёт резервные копии.
- **«Автосейв заблокирован»:** защита от перезаписи файла пустотой. Нажмите один раз «💾 Сохранить вручную» — дальше автосейв заработает.

## 📞 Перезвоны

Отдельная вкладка. Вверху — фильтры и статистика (просрочено / сегодня / будущие / архив).

- У каждого перезвона может быть **несколько тегов** (`today`, `upcoming`, `overdue`, `archived`), фильтры сортируют по их наличию. «Актуальные» не показывают будущие.
- **Карточка (2 строки):** время + местное время клиента (если задан пояс) + дата; имя клиента и телефон (клик по номеру — копирование, карточка подсвечивается и раскрывается история); полный комментарий; кнопки `✓ Дозвонился / × Удалить / ✎ Редактировать`. Ниже — результат `НО / АО / Сброс / Перезв.` и кликабельные ссылки (переход в CRM/админки).
- Клик по пустой зоне карточки раскрывает **только историю**. Клики по кнопкам, ссылкам и внутри формы переноса меню не раскрывают.
- **Поле «Причина»** при создании убрано — причина пишется в комментарий. Имя родителя и ученик подставляются только если реально заполнены в источнике данных.
- **Логика времени:** окно `[с … до]` — **информационное**, задаётся в МСК и определяет, когда карточка в «Актуальных». Статус зависит от времени дня, а не от даты (просрочен, только если «до» уже прошло сегодня).
- **Фактическое время следующего перезвона** — скрытый параметр (`nextDate`/`nextTime`). При автопереносе `НО/АО/Сброс` считается от **времени последнего звонка из истории** +3 часа (округление вниз до 00/30), например звонок в 16:31 → следующий 19:30 в тот же день. Окно С-ДО при этом **не меняется**. В карточке показывается мелко «следующий: ЧЧ:ММ».
- Ограничения: не чаще 3 попыток в день, правило «не звонить после 21:00 по местному времени клиента».
- **Настройка:** в **⚙ Редактор → Настройки → 📞 Перезвоны** — общие списки причин и результатов.

## 🧩 Режим «Работа»

- Переменные клиента, подстановка в текст через `{имя}`.

## 🔌 Интеграция с CRM/телефонией (Naumen + Tampermonkey)

Для автоматической передачи данных клиента в приложение используется расширение **Tampermonkey** и файл `naumen-to-script.example.user.js`.

### Установка
1. Установите **Tampermonkey** в браузере (Chrome/Edge).
2. Создайте новый скрипт и вставьте содержимое `naumen-to-script.example.user.js`.
3. Откройте страницу телефонии — появится плавающая кнопка **«▶ Передать в скрипт»**. При клике она передаёт в приложение данные текущего клиента (ссылку на карточку в CRM, телефон, имя родителя/ученика, класс).
4. Приложение должно быть открыто через локальный сервер (`http://localhost:8000/index.html`).

### Адаптация под свой колл-центр
Скрипт **универсальный** — все домены задаются через `localStorage` (в консоли браузера на странице телефонии). По умолчанию настроен на пример (Тетрика), но подходит для любых адресов.

| Что настроить | Команда в консоли | По умолчанию |
|---|---|---|
| Домен Naumen | `localStorage.setItem('rm_naumen_host', 'ВАШ_ДОМЕН')` | `tetrika.nau.team` |
| Домен CRM (Bitrix) | `localStorage.setItem('rm_crm_host', 'ВАШ_ДОМЕН_CRM')` | `bitrix.tetrika.school` |
| Вебхук Bitrix (для имени клиента) | `localStorage.setItem('rm_bitrix_webhook', 'https://ХОСТ/rest/ID/TOKEN/')` | пусто |
| Адрес приложения | `localStorage.setItem('rm_bridge_script_url', 'http://.../index.html')` | `localhost:8000` |

> `@match` в скрипте стоит `*://*/*` — работает на любом сайте. Если хотите ограничить конкретным доменом Naumen, замените `@match` вверху файла (пример есть в комментариях скрипта).

### Безопасность
`naumen-to-script.example.user.js` — это **шаблон без секретов**: в нём нет зашитых токенов и нет жёстко прописанных доменов компании. Вебхук задаётся через `localStorage` (см. выше). **Не вшивайте токены в код**, если планируете публиковать скрипт.

Рабочий файл с реальными данными (`naumen-to-script.user.js`) в репозиторий не выкладывается — он в `.gitignore`.

## ✏️ Синтаксис текста (кратко)

Работает везде, где есть текст реплики. Полная справка — в редакторе (кнопка «? Синтаксис»).

- Подстановки: `{var}`, `{class+1}`, `{a+b}`, `{map.ключ}`.
- Сворачиваемые блоки: `\\\Заголовок … \\\`, `\\\+` — открытый по умолчанию.
- Inline-выделение: `\!текст\!` (синее), `\!!текст\!!` (жёлтое).
- Копируемые блоки: `\%текст\%`.
- Условные блоки: `(условие)[да : нет]`.
- Ссылки на возражения: `(текст|ID)`.
- Условия: `var`, `!var`, `class>=5`, `mood==хорошее`, `a && b`, `a || b`, `list.length>0`.
- Несколько вариантов текста: массив строк в `text`.

## 🔧 Настройка автообновления

В файле `start.py` (в начале, в разделе настроек) есть переменные:

```python
REPO_OWNER = "ВАШ_ЛОГИН"
REPO_NAME = "ВАШ_РЕПО"
```

- Укажите владельца и имя вашего открытого репозитория — тогда при каждом запуске `start.py` получит список файлов через GitHub API и **автоматически обновит** все изменённые (`index.html`, `start.py`, скрипты запуска, userscript, README, CHANGELOG). `index.html` сравнивается по номеру версии, остальные — по содержимому.
- Если файла нет локально — он скачивается (полная установка в пустую папку).
- Оставьте `REPO_NAME` пустым — автообновление пропускается.

> Править нужно **только `start.py`** — файлы `start_win.bat` / `start_mac.command` лишь запускают его и настраивать не нужно.

## 🛠 Технические детали (для разработчика)

- **Стек:** один HTML-файл (JS/CSS инлайн), IndexedDB для хранения ссылок на файлы (FSA API).
- **Копирование в буфер:** `navigator.clipboard` с fallback на `execCommand`.
- **Перезвоны:** элемент `{id, date, timeFrom, timeTo, phone, parent, notes, reason, links, history[], tz, ignoreTz, archived, created}`. Теги — `callTags()`, статус — `callStatus()`; автосдвиг — `calcNextSlot` (окно + лимит 3/день + шаг 30 мин).
- **Часовые пояса:** `tz` = смещение UTC (МСК = 3), в UI — смещение от МСК.
